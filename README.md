# City of Columbus, OH

The civic record of **City of Columbus** (city), one jurisdiction at a time, in git.

| | |
|---|---|
| jurisdiction | `jur:us-oh:place:3918000` |
| level | `city` |
| parent | `jur:us-oh` |
| state | OH (US) |
| FIPS state / county / place | OH / 049 / 18000 |
| Census GEOID | 3918000 |
| OCD id | `ocd-division/country:us/state:oh/place:columbus` |
| ISO 3166-2 | US-OH |

Generated by `civic_repo_gen/0.1.0` from the Census of Governments, TIGERweb and the CC0
officials datasets. Regeneration never overwrites a person's correction: see
`CONTRIBUTING.md`.

## What is here

- `jurisdiction.json` — this jurisdiction: codes, parent, which global-law corpora
  cover it, the boundary pointer, and a coverage block that states the gaps.
- `records/body/` — every governing body (0).
- `records/office/` — every seat (0).
- `records/official/` — who holds a seat (10), with the source that says so.
- `records/source/` — every URL any record cites (10).
- `coverage.json` — counts and gaps; the validator checks it against the files.

There are no meeting or measure records yet. That is a stated gap, not a claim:
`coverage.json` names it and `tools/check.py` fails if the counts and the files
disagree.

## Check it yourself

```bash
python tools/check.py           # 0 clean, 1 violation, 2 could-not-judge
python tools/verify.py          # are the cited sources reachable right now?
python tools/build_site.py --out site
```

The rules are `civic-check/1`, pinned in `tools/civic_schema.py` and identified by
`tools/TOOLS_VERSION`. Every record is JSON with `provenance` (who added it, what
backs it, how it was validated) and `generation` (which generator built it and a
content hash). A `trust` value is never stored: it is computed from the evidence.

## Privacy

Public officials are public records. This repo never stores a home address, a
personal phone or email, a date of birth, or anything about a person's family.
`PRIVACY.md` says how that is enforced, and the validator enforces it.
